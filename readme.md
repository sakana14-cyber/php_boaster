# 給与タイマーアプリ（php_boaster）

アルバイト・パートで働くユーザーが、出勤と退勤を記録し、勤務中の予測給与や日別・月別の給与を確認できる Web アプリケーションです。

> **開発状況**  
> 現在は Laravel の初期セットアップ段階です。この README は、本アプリを実装する際の要件・設計方針・開発手順をまとめたものです。

## このアプリの目的

最も重要なユーザー体験は、次の一点です。

> 出勤ボタンを押すだけで、今いくら稼いでいるのか分かる。

機能・画面・データ構造は、次の優先順位で設計します。

1. 操作が簡単であること
2. 給与計算が正確であること
3. 現在の給与がひと目で分かること
4. スマートフォンで使いやすいこと
5. 勤務データが失われないこと
6. 後から機能を追加しやすいこと
7. 初学者にも読みやすく保守しやすいこと

## 主要機能

| 機能 | 概要 |
|---|---|
| ユーザー認証 | ログイン中のユーザーだけが自身のデータを操作する |
| 時給設定 | 1 円以上の整数で現在の時給を設定する |
| 出勤 | ボタンを押した日時と、その時点の時給を勤務記録へ保存する |
| 勤務中タイマー | 経過時間と予測給与をリアルタイム表示する |
| 退勤 | サーバー時刻を基に勤務時間と確定給与を計算・保存する |
| 日別履歴 | 日ごとの勤務明細と合計給与を表示する |
| カレンダー | 表示月の日別給与を一覧表示する |
| 月間集計 | 月間給与、勤務時間、勤務日数を表示する |
| 勤務記録の編集・削除 | 誤入力を修正し、給与と集計値を再計算する |

## 技術構成

PHP と Laravel をアプリケーションの中核として使用します。

| 分類 | 技術 | 用途 |
|---|---|---|
| バックエンド | PHP 8.3 以上 | アプリケーションロジック |
| フレームワーク | Laravel 13 | ルーティング、認証、検証、ORM、テスト |
| UI | Blade | サーバーサイドレンダリング |
| CSS | Tailwind CSS 4 | モバイルファーストの画面設計 |
| JavaScript | Vanilla JavaScript | 勤務中タイマーなど必要最小限の動的表示 |
| ビルド | Vite 8 | CSS・JavaScript の開発とビルド |
| データベース | SQLite（開発時） | ユーザー、時給、勤務記録の保存 |
| テスト | PHPUnit 12 | 単体・機能テスト |

アプリケーション本体は [`laravel/`](laravel) に配置されています。初期段階では単一の Laravel アプリとして構成し、別のフロントエンド SPA や API サーバーへ不用意に分割しません。

## システム設計

### 責務の分担

- Laravel は認証、入力検証、勤務状態の管理、確定給与の計算、DB 更新を担当する
- Blade は Laravel が返した状態を安全に表示する
- JavaScript は、サーバーから受け取った出勤日時と適用時給を使って予測表示だけを更新する
- 予測給与の更新を目的として毎秒 API や DB へアクセスしない
- 退勤時の確定値はブラウザの計算結果を信用せず、Laravel 側で再計算する

### 推奨ディレクトリ構成

実装時は Laravel の標準構成を保ち、役割を次のように分離します。

```text
laravel/
├── app/
│   ├── Actions/WorkSessions/    # 出勤・退勤などのユースケース
│   ├── Http/Controllers/        # HTTP リクエストの受付
│   ├── Http/Requests/           # 入力バリデーション
│   ├── Models/                  # User、WorkSession など
│   └── Services/                # 給与計算・集計処理
├── database/
│   ├── factories/
│   ├── migrations/
│   └── seeders/
├── resources/
│   ├── css/
│   ├── js/
│   └── views/
├── routes/web.php
└── tests/
    ├── Feature/
    └── Unit/
```

過度な抽象化は避けますが、給与計算を Controller や JavaScript に重複して記述しないため、サーバー側の計算処理は専用クラスへ集約します。

### データモデル

#### users

| カラム | 型の例 | 内容 |
|---|---|---|
| `id` | bigint | 主キー |
| `name` | string | ユーザー名 |
| `email` | string | ログイン用メールアドレス |
| `password` | string | ハッシュ化済みパスワード |
| `hourly_wage_default` | unsigned integer | 基本時給（円） |
| `hourly_wage_weekend_holiday` | unsigned integer | 土日祝時給（円）。曜日から自動判定して適用する |
| `rounding_unit_shift` | unsigned integer | 勤務中の端数切り捨て単位（分） |
| `rounding_unit_edge` | unsigned integer | 出退勤打刻前後の端数切り捨て単位（分） |
| `created_at` / `updated_at` | timestamp | 作成・更新日時 |

#### special_wages

ユーザーが任意に登録する時間帯指定の特別給（深夜給など）です。1 ユーザーにつき複数登録できます。

| カラム | 型の例 | 内容 |
|---|---|---|
| `id` | bigint | 主キー |
| `user_id` | foreign key | 所有ユーザー |
| `title` | string | 名称（例: 深夜給） |
| `start_time` | time | 適用開始時刻 |
| `end_time` | time | 適用終了時刻 |
| `hourly_wage` | unsigned integer | この時間帯に適用する時給（円） |
| `created_at` / `updated_at` | timestamp | 作成・更新日時 |

#### work_sessions

| カラム | 型の例 | 内容 |
|---|---|---|
| `id` | bigint | 主キー |
| `user_id` | foreign key | 勤務したユーザー |
| `scheduled_start_at` | nullable datetime | 予定出勤日時（カレンダーで事前入力するシフト） |
| `scheduled_end_at` | nullable datetime | 予定退勤日時 |
| `actual_start_at` | nullable datetime | 実際の出勤日時（打刻）。`NULL` は未出勤 |
| `actual_end_at` | nullable datetime | 実際の退勤日時（打刻）。`NULL` は勤務中または未実施 |
| `earned_amount` | nullable unsigned integer | このセッションで確定した給与（円） |
| `created_at` / `updated_at` | timestamp | 作成・更新日時 |

過去の給与を変えないため、給与計算は打刻時点の `users`／`special_wages` の設定値で行い、退勤時に `earned_amount` として確定・保存します。ユーザーが後から時給や特別給を変更しても、確定済みの `earned_amount` は再計算しません。

## 業務ルール

### 給与計算

給与は分や時間ではなく、秒単位で計算します。適用時給は勤務区間を時間帯・曜日ごとに分割し、区間ごとに次の優先順位で決定します。

1. `special_wages` に登録された時間帯と重なる部分は、その `hourly_wage`
2. 勤務日が土日祝なら `hourly_wage_weekend_holiday`
3. どちらにも該当しなければ `hourly_wage_default`

特別給の時間帯と土日祝が重なる場合は、特別給を優先します。

```text
勤務秒数 = 退勤日時 - 出勤日時（rounding_unit_shift 分単位で切り捨て）
区間ごとの給与 = floor(区間の適用時給 × 区間の勤務秒数 ÷ 3600)
給与 = 区間ごとの給与の合計
```

例：時給 1,200 円で 1 時間 30 分（5,400 秒）勤務した場合

```text
floor(1200 × 5400 ÷ 3600) = 1,800 円
```

- 勤務中に表示する金額は「予測給与」とする
- 退勤後に Laravel が計算して保存した金額は「確定給与」とする
- 出退勤の打刻時刻は `rounding_unit_edge` 分単位で丸めてから実働時間を算出する
- 1 円未満は切り捨てる
- 端数処理・時給の優先判定は給与計算クラス（`app/Services/SalaryCalculator.php`）の一か所に集約する
- 金額は `123,456円` の形式で表示する

### 出勤・退勤

- 同じユーザーが同時に複数の勤務を開始することはできない
- 勤務中でなければ退勤できない
- 退勤日時は出勤日時より後でなければならない
- 出勤・退勤時刻は Laravel が取得したサーバー時刻を使用する
- ボタンは送信開始から完了まで無効化する
- サーバー側でもトランザクションや制約を用いて二重処理を防ぐ
- ブラウザを閉じても、DB の未退勤レコードから勤務状態を復元する

### 時刻と日付

- アプリケーションの基準タイムゾーンは `Asia/Tokyo` とする
- DB とアプリケーションの日時管理方式を統一する
- 日付をまたぐ勤務も正しい勤務秒数で計算する
- 日別集計は原則として勤務開始日に計上する
- 将来、日付境界で勤務を分割できるよう、集計処理を独立させる

### カレンダーと集計

- 同じ日に複数回勤務した場合は、その日の確定給与と勤務時間を合算する
- 月間給与は表示対象月に属する確定勤務のみを集計する
- 月間勤務日数は勤務開始日の重複を除いて数える
- カレンダー用の取得範囲は表示中の月に限定し、全履歴を毎回取得しない

### データ整合性とセキュリティ

次の状態を許可しません。

- 時給、勤務秒数、給与が負数または不正な値になる
- 存在しない勤務を退勤・編集・削除する
- 他のユーザーの時給や勤務記録を閲覧・変更する
- フロントエンドが送信した給与や勤務秒数をそのまま保存する
- バリデーションなしで入力値を利用する

Laravel の認証、認可、CSRF 保護、Form Request、Eloquent のバインディングを利用し、SQL インジェクション、XSS、CSRF など一般的な脆弱性を防ぎます。

## 画面構成

### ホーム

情報を詰め込みすぎず、現在の状態と主操作を最優先にします。

勤務していない場合：

```text
今日の給与
0円

[ 出勤する ]
```

勤務中の場合：

```text
勤務中
03:42:18

現在の予測給与
4,445円

[ 退勤する ]
```

その下に今月の給与、勤務時間、勤務日数を表示します。ユーザーがアプリを開いてから 1〜2 回以内の操作で出勤できることを目標とします。

### カレンダー・日付詳細

- カレンダーには日ごとの合計給与を表示する
- 日付を選ぶと、出勤時刻、退勤時刻、勤務時間、適用時給、給与を表示する
- 同日に複数の勤務がある場合は明細を分けて表示する

### 設定

- 現在の時給を確認・変更できる
- 0 円以下、小数、整数以外は登録できない
- 時給変更が過去の確定給与へ影響しないことを明示する

### UI 方針

- シンプルでモダンなモバイルファースト設計とする
- 現在の給与と出勤・退勤ボタンを最も目立たせる
- iPhone、Android、PC で横スクロールを発生させない
- 通信中はローディングを表示し、操作対象を一時的に無効化する
- 失敗時は次の行動が分かるエラーメッセージを表示する

## セットアップ

### 必要環境

- PHP 8.3 以上
- Composer
- Node.js / npm
- PHP SQLite 拡張（`pdo_sqlite`）

### インストール

```bash
git clone <repository-url>
cd php_boaster/laravel
touch database/database.sqlite
composer run setup
```

`composer run setup` は依存関係のインストール、`.env` の作成、アプリケーションキー生成、マイグレーション、フロントエンドのビルドを実行します。

個別に実行する場合：

```bash
cd laravel
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate
npm install
npm run build
```

### 開発サーバー

```bash
cd laravel
composer run dev
```

起動後、原則として `http://localhost:8000` を開きます。終了する場合は `Ctrl+C` を押してください。

### よく使うコマンド

```bash
# テスト
composer test

# PHP のコード整形
./vendor/bin/pint

# DB を作り直してシードを投入（既存の開発データは消える）
php artisan migrate:fresh --seed

# 本番用アセットの生成
npm run build
```

## テスト方針

給与計算は Unit テスト、認証・出勤・退勤・履歴・集計は Feature テストを中心に検証します。最低限、次のケースを自動テストします。

- 正常に出勤・退勤できる
- 二重出勤できない
- 出勤していない状態では退勤できない
- 多重送信でも勤務記録や退勤処理が重複しない
- 1 時間勤務の給与が時給と一致する
- 30 分勤務の給与が時給の半額になる
- 1 円未満が切り捨てられる
- 時給変更後も過去の給与が変わらない
- 同日複数勤務が正しく合算される
- 月間給与、勤務時間、勤務日数が正しく集計される
- 日付をまたぐ勤務時間が正しい
- ページ更新後も勤務中状態を復元できる
- 他ユーザーのデータを閲覧・変更できない

## 開発ルール

- 既存の Laravel 標準構成と正常なコードを尊重し、必要最小限の変更を行う
- UI、HTTP 処理、業務ロジック、DB 操作、給与計算の責務を分離する
- 給与計算、日時処理、金額表示、日付表示を複数箇所へコピーしない
- 意味が伝わるクラス名・メソッド名・変数名を使う
- コードから分かる内容ではなく、判断理由が必要な箇所にコメントを書く
- DB の変更はマイグレーションで行い、既存データへの影響を確認する
- 標準機能や既存依存で実装できる場合は、新しいライブラリを追加しない
- 仕様変更や機能削除を独断で行わない
- 変更後はコード整形、関連テスト、全体テストを実行する
- ブランチ運用・コミットメッセージの書き方は [CONTRIBUTING.md](CONTRIBUTING.md) に従う
